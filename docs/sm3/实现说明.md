# PostgreSQL 17.10 与 pgJDBC 42.7.3 的 SCRAM-SM3 实现

本文件说明最终实现；部署、Nexus 上传及 Java 项目验收见《Linux部署与Java验证.md》。历史 implementation-plan 文件仅用于追溯编码前分析。

## 协议及口令格式

- 配置/HBA 名称：`scram-sm3`；SASL 机制：`SCRAM-SM3`。
- verifier 格式：`SCRAM-SM3$<iterations>:<base64 salt>$<base64 StoredKey>:<base64 ServerKey>`。
- 采用 PBKDF2-HMAC-SM3、HMAC-SM3 和 SM3，密钥/摘要长度 32 字节；随机盐默认 16 字节，默认迭代 4096。
- 沿用 PostgreSQL SCRAM 消息和 SASLprep/失败回退语义。客户端证明与服务端签名均须验证成功才能完成认证；不是仅替换数据库里的口令前缀。
- 首版实现普通 SM3，可在 TLS 内使用；没有 `SCRAM-SM3-PLUS`。SHA256 的 PLUS 路径继续保留。
- 这是配套两个 fork 的自定义扩展；使用相同散列算法不代表兼容 openGauss 认证协议。官方 PostgreSQL/官方 pgJDBC 42.7.3 不具备此扩展。

## PostgreSQL 修改位置

| 层次 | 主要文件 | 行为 |
|---|---|---|
| 构建检测 | `configure.ac`、`configure`、`meson.build` | 检测 OpenSSL `EVP_sm3`，生成 `HAVE_EVP_SM3`。 |
| 公共算法 | `src/common/cryptohash*`、`hmac*`、`scram-common.c` | 增加 PG_SM3，复用 SCRAM 派生与 verifier 生成，OpenSSL 实现 SM3；不支持的构建明确失败。 |
| 服务端 | `src/backend/libpq/auth-scram.c`、`auth.c`、`crypt.c` | 独立 SM3 descriptor，仅广告普通 SM3；口令识别、明文验证、空口令检查、未知用户伪认证均感知算法。 |
| 配置 | `hba.c`、`guc_tables.c`、相关 include | 条件开放 `scram-sm3`，保留 SHA/MD5 机制及错误行为。 |
| 初始化 | `src/bin/initdb/initdb.c` | 支持 `--auth-host=scram-sm3`，生成 SM3 超管口令、持久化默认算法，拒绝互相冲突的初始化认证配置。 |
| 客户端 | `src/interfaces/libpq/fe-auth*`、`fe-connect.c` | SM3 登录、密码 API、`require_auth=scram-sm3` 精确限制；跨 PQreset 保留策略；强制完整握手。 |

`password_encryption='scram-sm3'` 只控制之后生成的口令，不会把现有 SHA/MD5 verifier 转换成 SM3。HBA 与保存的 verifier 算法不匹配会拒绝，不会为 SM3 自动降级到旧算法。

服务端生成 SM3 verifier 复用现有 `scram_iterations` GUC。JDBC 的 `PasswordUtil`/`alterUserPassword` 默认生成 4096 次迭代的 verifier（沿用 SHA256 API 的固定默认方式）；第三参数为 null 时跟随服务器的**算法**，不会读取服务器迭代值。需要自定义迭代时使用 `PasswordUtil.encodeScramSm3(char[], int, byte[])`，再由授权管理代码设置返回的 verifier。不要记录明文口令或完整 verifier。

## JDBC 修改位置

| 文件 | 行为 |
|---|---|
| `Sm3ScramMechanism.java` | BC 轻量算法 API：SM3、HMAC、PBKDF2、verifier；不注册全局 JCA Provider。 |
| `PgSm3SaslPrep.java` | PostgreSQL 17.10 的 Unicode 3.2 范围和映射顺序，包括 PostgreSQL 对禁止字符/空映射结果的原文回退。 |
| `Sm3ScramSession.java` | 普通 SCRAM-SM3 的 nonce、salt、迭代、proof、签名与阶段检查；拒绝重复属性和未知必需扩展。 |
| `ScramAuthenticator.java` | 有界读取机制列表，选择 SM3 或保留原 SHA256 OnGres 流程，记录服务端验证完成状态。 |
| `ConnectionFactoryImpl.java` | 认证中途不能切换机制，只有签名验证完成后才能接受 AuthenticationOk。 |
| `PasswordUtil.java`、`PGConnection.java` | 增加 SM3 verifier/改密 API 分派，清零传入的口令字符数组。 |
| `pgjdbc/build.gradle.kts`、`reduced-pom.xml` | 锁定算法依赖，打包并重定位至驱动内部，避免业务应用额外配置 BC 或依赖其 Provider。 |

定制 release 使用 `org.postgresql:postgresql:42.7.3-sm3.1`，不覆盖官方 `42.7.3`。算法库可选多版本目录不进入 Java 8 驱动包，使用库的 Java 8 基础实现；签名文件和 BC Provider 自动发现入口不随重定位包发布。实际许可文件随最终 JAR 附带。

## 可复现构建

Linux PostgreSQL 构建示例：

```sh
# 先安装 C 编译器、make、bison、flex、pkg-config、OpenSSL/ICU/readline/zlib 开发包。
mkdir build-sm3
cd build-sm3
../configure --prefix=/opt/postgresql-sm3 --with-ssl=openssl --with-icu --enable-tap-tests
make -j4
make install
# TAP 需 Perl IPC::Run 等测试依赖；测试不能使用 root 数据库进程。
make check
make -C src/test/authentication check PROVE_TESTS='t/001_password.pl t/002_saslprep.pl t/007_scram_sm3.pl'
make -C src/interfaces/libpq check PROVE_TESTS='t/001_uri.pl t/002_api.pl t/006_sm3.pl'
```

公共算法独立向量测试见 `doc/sm3/tests/README.md`。Docker 构建脚本见 `deploy/sm3/build-and-push.sh`，运行目录为完整修改后的源码树。

JDBC 构建（仓库根目录，Gradle 运行使用 JDK 17，目标 Java 8）：

```sh
./gradlew :postgresql:test --tests org.postgresql.jre7.sasl.Sm3ScramTest :postgresql:styleCheck -PskipJavadoc
./gradlew :postgresql:assemble -Prelease -PskipJavadoc -x :postgresql:signPostgresqlPublication -x :postgresql:publishPostgresqlPublicationToTmp-mavenRepository
```

此命令生成私有 Nexus 使用的未做 GPG 发布签名的产物；跳过上游发布签名任务不影响 SCRAM 登录时的服务端签名验证。

最终运行/发布使用包含依赖的主驱动 JAR，不能使用中间的 thin/shadow 输入 JAR。交付包内固定主 JAR、POM 和校验和可直接用于 Nexus 上传；测试结果和实际镜像 digest 见交付验证记录。
